# StoryVerse 变更记录

本文档记录每次明确要求“记录”时，StoryVerse 相比上一条记录所发生的变化。记录按时间倒序维护；第一条以 GitHub 克隆版本为基线，后续记录以上一条完成时的本地版本为基线。

## 记录 003 — Supabase 正式后端、完整产品闭环与实验埋点发版

- 记录日期：2026-08-20
- 对比基线：记录 002 完成时的本地纯前端版本
- 当前形态：React + TypeScript + Vite 前端，Supabase 数据库/Auth/Storage/Edge Functions 后端，火山方舟 AI 与完整实验埋点

### 原本的问题

1. 账号、草稿、故事和互动仍依赖浏览器本地数据，无法跨设备使用，也没有可靠的权限隔离。
2. AI 审核、标签、推荐分数和图片主要是演示逻辑，故事发布、待审和恢复状态无法形成稳定闭环。
3. 管理员页面功能不足，冷启动、人工审核、账号、故事、配置和实验数据缺少统一管理入口。
4. StarLobby 使用假推荐和旧分类，故事距离、类型颜色、翻译、互动限制和共鸣刷新行为不完整。
5. 用户提交故事后退出，可能卡在“还没有公开”，返回时又被引导写新故事。
6. 网站缺少可追溯的实验行为事件、账号下钻和数据质量验证。

### 现在的状态

1. 正式数据统一进入 Supabase，RLS 保证用户只能访问自己的草稿、私密/待审故事和通知；公开故事才允许其他用户读取。
2. 故事流程覆盖草稿、AI 处理中、人工审核、等待确认、公开、私密、待修改和下架，并支持刷新或重新登录后恢复原进度。
3. 火山方舟负责安全审核、21 类单选、两个主题、两组 1024 维 Embedding、英文翻译和唯一故事图片。
4. StarLobby 展示 Top 15，本人最近发布故事固定在中心，其他故事径向距离由 `cityScore` 决定，颜色由最终类型决定。
5. 管理员后台支持账号、故事、人工审核、AI 任务、冷启动、类型颜色、推荐权重、反馈和实验行为看板。
6. 全站 P0/P1/P2 语义埋点已接入 Supabase，可按账号、时间、优先级和行为模块筛选并下钻到参与者时间线。
7. 图片素材已压缩为 WebP，主要页面按需加载；冷启动源文件和转换产物保持本地，不进入公开代码仓库。

### 本次主要变化

- 建立 Supabase 迁移、RLS、Auth、Storage、Queue、推荐函数、分析表和管理员查询接口。
- 接入账号注册、登录、密保找回、停用恢复、管理员角色和密码重置。
- 接入服务端柔性安全审核、人工复核、21 类标签、主题、Embedding、翻译和 Seedream 图片生成。
- 实现故事恢复、唯一图片生命周期、英文按需翻译、自身故事禁止点赞/举报和互动反馈。
- 实现基于城市、人生阶段、主题与语义的推荐批次，以及大厅共鸣确认后的重新排序。
- 重构管理员 UI 和实验数据看板，隐藏公开页面的管理员入口。
- 新增本地一键开发、数据库测试、边界测试、AI/图片 E2E、线上冒烟和埋点 QA 脚本。
- 建立分析指标、事件字典、参数字典、QA 清单和 ANA-01 至 ANA-12 页面截图。

### 发版前验证

- Vitest：15 个文件、80 项测试通过。
- pgTAP：57 项数据库测试通过。
- 本地完整 E2E：21 个检查点通过，包含真实 AI、Embedding、图片和 Storage。
- Edge Function/数据库边界：299 项断言通过；记录 1 个仅限本地模拟网关的 CORS 差异。
- 审核：8/8 风险类别进入人工审核，未成年人和危机内容优先级正确。
- 埋点：本地 24/24 合约检查通过。
- TypeScript、Vite 生产构建、Prettier 和 Git 差异检查通过。

## 记录 002 — 故事信息规则、StoryPage 布局与发布后流程修正

- 记录日期：2026-08-16
- 对比基线：记录 001 完成时的本地版本
- 当前形态：保持原有视觉风格的纯前端本地版本，故事填写、确认、发布后访问与本地登录规则进一步统一

### 原本的问题

1. StoryWrite 中年龄和性别虽然存在，但没有被完整纳入必填校验；用户漏填时，提示也不能准确列出所有缺失信息。
2. “故事发生在”与按部分选项额外出现的“人生阶段”同时存在，表达重复，字段来源和显示条件不一致。
3. StoryPage 虽然允许修改正文，但没有在最终发布环节完整保证正文仍处于 100–1500 字范围内。
4. 图片风格仍包含需要删除的旧选项和说明文案，界面与当前产品选择不一致。
5. StarLobby 把星星颜色描述为对应“主题”，但实际颜色表达的是故事“类型”；部分内部变量也继续沿用 `theme` 命名。
6. 登录异常处理范围过大，错误账号或密码可能被当作浏览器存储不可用，错误进入临时预览账号。
7. StoryPage 删除“时间”后仍沿用旧字段网格，导致字段缺位、底部排版不完整；新手引导中也残留“时间”和旧图片风格名称。

### 现在的状态

1. StoryWrite 的故事正文、写完后的感受、人生阶段、城市、年龄、性别和故事人物全部属于必填信息，缺失时会显示对应字段名称。
2. 原“故事发生在”已经彻底删除，只保留统一的“当时所处的人生阶段”，候选项固定为学龄期、青春期、成年早期、成年中期和老年期。
3. StoryPage 继续允许修改正文，并在输入框、按钮状态和最终发布动作三处统一执行 100–1500 字限制。
4. 图片风格只保留 3D粘土风、独立杂志风和复古拼贴风；日本画风、旧素材及“生图是可选项……”说明已经删除。
5. StarLobby 的用户文案统一为“颜色对应不同的类型”，相关页面内部命名也改为 `category`，不再用 `theme` 表示颜色分类。
6. 登录会校验当前浏览器本地保存的账号和密码；只有浏览器存储确实不可用时才进入临时预览账号。
7. StoryPage 信息区现在固定为：第一行“故事标题、地点”，第二行“年龄、性别、当时所处的人生阶段”；桌面及一般窄窗口保持完整三列，手机宽度下自动改为单列。

### 本次做了什么

#### 1. 统一故事字段与必填规则

- 从 `StoryDraft`、默认草稿、状态保存、故事处理和页面组件中删除旧 `time` 字段，不保留兼容分支。
- 将人生阶段整理为一个始终显示的必填字段，并统一中英文名称和五个候选项。
- 把年龄和性别纳入 StoryWrite 必填校验及缺失提示。
- 抽取共用的年龄输入组件，使 StoryWrite 和 StoryPage 使用同一套数字过滤、三位长度限制和单位显示规则。

#### 2. 完善 StoryPage 编辑与排版

- StoryPage 增加年龄字段，并把信息顺序整理为“标题、地点、年龄、性别、人生阶段”。
- 更新信息网格：标题与地点各占半行，年龄、性别和人生阶段各占三分之一行，删除失效的旧跨列样式。
- 调整响应式规则，避免一般窄窗口过早切成两列；手机断点下再改为单列。
- 正文编辑框限制最多 1500 字，少于 100 字或超过范围时禁止发布，并在发布函数中再次校验。

#### 3. 清理图片风格和页面引导

- 删除日本画风选项、类型、映射、默认值和对应图片素材。
- 默认图片风格改为 3D粘土风，只保留三种当前支持的风格。
- 删除图片生成为可选项的旧说明段落。
- 同步修正 StoryPage 新手引导：删除“时间”，加入“年龄”，并替换已经删除的旧图片风格名称。

#### 4. 修正 StarLobby 类型命名

- 把引导文案“颜色对应不同的主题”改为“颜色对应不同的类型”，同步调整英文文案和页面图例。
- 将 StarLobby 内部用于颜色分类的 `theme`、`themeColors`、`themeMap` 等名称改为对应的 `category` 命名。
- 保留故事领域本身真实表示主题的 `story.theme`，避免把“故事主题”和“颜色类型”混为一谈。

#### 5. 收紧登录与发布后页面访问

- 错误账号或密码现在会返回明确的登录错误，不再静默进入预览账号。
- 临时预览回退只处理浏览器存储不可用这一种情况。
- Resonance、Recommendations 和 StarLobby 统一使用“当前账号是否拥有已发布故事”进行访问保护；没有第一篇已发布故事的用户仍需先完成写作。

#### 6. 补充自动验证

- 新增人生阶段候选项、旧时间字段删除、年龄与性别必填、正文长度边界及图片风格集合测试。
- 新增 StoryPage 与 StarLobby 引导文案测试，防止旧字段、旧风格和错误的“主题”表述再次出现。
- 新增错误登录不能建立会话，以及发布后页面访问保护测试。

### 验证结果

- `npm test`：6 个测试文件、52 项测试全部通过。
- `npm run build`：TypeScript 检查和 Vite 生产构建通过。
- 已在本地浏览器实际检查 StoryWrite 和 StoryPage 的字段、必填提示、正文边界、图片风格与 StoryPage 最终排版。
- 验证生成的 `dist/` 已删除，没有把编译产物重新留在项目中。

### 当前已知边界

- 本地账号只存在于注册时所用浏览器及对应网址下；`localhost`、`127.0.0.1` 或不同端口之间不会共享账号。
- 当前账号密码经过哈希后保存在浏览器本地，但仍属于演示级本地登录，不等同于正式服务端身份认证。
- 图片“生成”和故事“AI 分析”仍是纯前端本地演示逻辑，不会请求真实生成式 AI 后端。
- 生产构建仍会提示主 JavaScript 包较大，但不影响构建成功或当前页面呈现。

## 记录 001 — 前端架构清理与首次访问流程修正

- 记录日期：2026-08-16
- 对比基线：[GitHub 仓库](https://github.com/chelsealeezc/StoryVerse)提交 `acf43c557fa5b9cff4b3b59b3d74911ef7400164`（2026-08-15，`Update image style preview artwork`）
- 当前形态：保持原网站视觉和交互的纯前端本地版本

### 原本的问题

1. 前端、服务端、数据库和云部署代码混在同一个项目中，同时包含 Express、PostgreSQL、Drizzle、Docker、CloudBase 和阿里云相关内容，项目边界不清楚。
2. 大量页面、状态、接口调用和业务规则集中在少数超大文件中，例如原 `src/App.tsx` 超过 2,300 行，阅读、定位和回归都很困难。
3. 文件和变量同时使用 `wizard`、`atlas`、`galaxy`、`lobby` 等多套名称，同一个页面存在多个叫法。
4. 前端直接依赖后端账户、草稿、故事、图片生成和语音接口；删除后端后，原有流程无法独立运行。
5. 浏览器状态、账号数据、草稿恢复和页面导航相互耦合，旧账号留下的状态可能影响新账号。
6. 首次故事判断存在错误：代码曾把“当前没有草稿”视为“已经完成第一篇故事”，导致没有发布过故事的用户可能直接进入 StarLobby。
7. 生成目录、源码、部署文件和测试文件混在一起，缺少清晰的目录职责说明和维护规则。

### 现在的状态

1. 项目已经整理为 React、TypeScript 和 Vite 驱动的纯前端网站，不再包含自建服务器、数据库和云厂商部署层。
2. 首页、故事编辑、共鸣选择、推荐、StarLobby、引导和审核演示按功能归档；全局流程、共享组件、数据、服务、工具和类型各自拥有明确目录。
3. 原网站的页面布局、文案、响应式样式、动画、三维星图、新手引导和主要交互得到保留。
4. 账号、草稿、故事、偏好、互动、举报和反馈保存在当前浏览器的 `localStorage` 中，不上传到 StoryVerse 自建后端。
5. 城市搜索、经纬度记录、浏览器语音输入、故事图片预览与下载等前端功能继续可用；地点搜索失败时会退回内置城市数据。
6. 页面和领域命名已经统一：故事编辑使用 `StoryEditor` / `storyEditor`，星空大厅使用 `StarLobby` / `starLobby`；`Galaxy` 只表示 StarLobby 内部的三维场景。
7. 新用户必须先写并发布故事。只有当前账号确实拥有已发布故事、同时没有待续写草稿时，登录后才会直接进入 StarLobby。

### 本次做了什么

#### 1. 删除服务端与云端内容

- 删除 `server/`、`functions/`、`drizzle/`、数据库初始化、Docker Compose、API Dockerfile 和服务端 TypeScript 配置。
- 删除阿里云、CloudBase 等部署说明和对应环境变量模板。
- 删除服务端身份认证、数据库访问、云端图片生成和服务端语音转写实现。
- 精简 `package.json` 和锁文件，只保留当前纯前端运行所需依赖。

#### 2. 重组前端目录

- `src/app/`：全局状态、页面调度和路由。
- `src/features/`：按页面体验拆分首页、故事编辑、共鸣、推荐、StarLobby、引导和审核台。
- `src/components/`：跨功能共享的品牌和界面组件。
- `src/services/`：本地数据、地点搜索、语音输入、故事图片和故事处理。
- `src/lib/`：状态持久化、草稿恢复、正文提示和内容安全规则。
- `src/data/`、`src/types/`、`src/styles/`：分别存放稳定数据、共享类型和全局样式。

#### 3. 建立纯前端数据边界

- 新增浏览器本地数据服务，统一处理注册、登录、草稿、发布、故事列表、偏好、互动、举报和反馈。
- 保留稳定的服务接口，让页面组件不直接操作 `localStorage`、浏览器语音接口或外部地点请求。
- 保留内置示例故事用于页面展示；示例数据不属于服务端用户数据。

#### 4. 统一命名并保留旧数据迁移

- 将原 `wizard` 统一为 `storyEditor`，原 `atlas` / 页面级 `galaxy` 统一为 `starLobby`。
- 文件、组件、函数、变量和类型分别采用统一的 PascalCase、camelCase 和 kebab-case 约定。
- 旧名称只保留在本地状态迁移逻辑中，避免已有浏览器数据升级后失效。

#### 5. 修正首次访问和登录跳转

- 使用“当前账号拥有的已发布故事数量”判断是否完成第一篇故事，不再使用“是否存在草稿”推断。
- 新注册用户、没有发布故事的登录用户以及存在草稿的用户都会进入故事编辑器。
- 直接访问 `/StarLobby` 也会检查第一篇故事状态；未发布故事的账号不能绕过创作流程。
- 未登录直接访问 `/StarLobby` 时返回首页。
- 新账号开始创作时清除可能来自旧浏览器状态的草稿和分析结果。

#### 6. 补充文档和自动验证

- 重写 README，说明当前产品能力、数据边界、目录结构、本地运行和验证方法。
- 新增 `docs/architecture.md`，明确依赖方向、目录职责、命名约定和视觉一致性约束。
- 测试覆盖本地账户与故事流程、旧数据迁移、内容安全、地点搜索以及新用户路由规则。
- GitHub Pages 构建调整为纯前端静态发布，并保留前端路径回退。

### 验证结果

- `npm test`：4 个测试文件、43 项测试全部通过。
- `npm run build`：TypeScript 检查和 Vite 生产构建通过。
- 本次首次访问逻辑修正未改动页面结构和 CSS。
- 验证生成的 `dist/` 已删除；它和 `node_modules/` 都是可重新生成的目录，不属于源码。

### 当前已知边界

- 账户和故事只保存在当前浏览器，暂不支持跨设备同步、真实多人账户或服务端权限控制。
- 中文地点搜索可以使用原项目保留的高德行政区划查询；它是可选外部请求，不是 StoryVerse 后端，离线时会自动退回内置数据。
- 语音识别由浏览器提供，支持情况和是否使用浏览器厂商的网络服务取决于用户所用浏览器。
- Three.js、动画和大幅背景素材使生产包仍然较大，构建会给出包体积提示，但不影响构建成功和当前页面呈现。
